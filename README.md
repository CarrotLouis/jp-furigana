# 日语歌词振假名 Plus · jp-furigana-plus

为网易云音乐 PC 客户端的日语歌词添加振假名，支持 **网易云音译、离线词典、外部歌词网站，以及逐词人工纠音**。

本分支由 CarrotLouis 长期独立维护，商店名称为「日语歌词振假名 Plus」，标识为 `jp-furigana-plus`，在 manifest 中以 `fork_of: "jp-furigana"` 标注来源。独立版以 **`standalone` 分支**发布，`main` 保留向上游贡献的版本。

这是 [Leleawa/jp-furigana](https://github.com/Leleawa/jp-furigana) 的扩展分支，保留上游的词典、罗马音对齐和逐字歌词适配。在此基础上增加网站取词、代理与自动重试、本地歌词管理和 RefinedNowPlayingNext 播放页编辑。相关改动见 [上游 PR #7](https://github.com/Leleawa/jp-furigana/pull/7)。

## 新特性一览

| 功能 | 说明 |
| --- | --- |
| 外部网站注音 | 从 UtaTen 获取词级振假名，或从歌ネット获取罗马音并对齐；可自动选择或只使用其中一个网站 |
| 更灵活的歌曲匹配 | 歌手写法不匹配时，尝试只搜索歌名，再用多个歌词片段核对同名候选 |
| 独立代理与重试 | 可为歌词网站单独配置代理；支持手动重新获取，以及可关闭的失败自动重试 |
| 播放页设置 | 适配 RefinedNowPlayingNext 3.0.2，在「歌词」后增加「注音」设置入口 |
| 人工纠音 | 在播放页逐词修改读音、保存和恢复；没有网站歌词的歌曲也可以编辑 |
| 本地歌词管理 | 每首歌一份 JSON，支持自定义目录、搜索、查看、空间统计、播放并编辑和删除 |
| 漏注音与排版修复 | 改善旧字体、部分未知汉字的注音，调整相邻汉字与长振假名的间距，减少重叠 |

## 安装与开始使用

### 环境

- Windows 版网易云音乐 **高于 3.1.11**；商店版范围与 RNP 依赖保持一致。
- [BetterNCM 1.3.4](https://github.com/std-microblock/chromatic/releases/tag/1.3.4)。
- 外部网站获取需要 Windows 自带的 PowerShell 5.1 和 `curl.exe`（Windows 10 1803 或更新版本）。
- 依赖 **RefinedNowPlayingNext**，播放页设置已适配 **3.0.2**；商店清单使用插件标识声明依赖，不能锁定具体版本。

不同客户端版本和歌词插件的页面结构可能不同，具体测试范围见 [验证记录](docs/validation.md)。**原生桌面歌词窗口不支持注音。**

### 安装

1. 获取独立版 `jp-furigana-plus.plugin`：查看 [Releases](https://github.com/CarrotLouis/jp-furigana/releases)，选择明确标注 Plus 的包；也可从 [standalone 的 CI](https://github.com/CarrotLouis/jp-furigana/actions/workflows/ci.yml?query=branch%3Astandalone) 下载 `jp-furigana-plus-plugin` artifact，或按下方方法自行打包。
2. 退出网易云音乐，将插件包放入实际 BetterNCM 数据目录下的 `plugins/`。默认通常为 `C:\betterncm\plugins`，自定义安装请以实际目录为准。
3. 如果已经安装上游版或旧版，把旧包备份到插件目录以外，再放入新包；Plus 与原版功能重叠，请只启用一个版本；检测到原版同时加载时，Plus 会显示冲突提示并暂停。
4. 启动网易云，进入「BetterNCM → 插件 → 日语歌词振假名 Plus」，将「读音来源」选为 **外部网站**。
5. 确认已安装 RefinedNowPlayingNext（已适配 3.0.2），播放日语歌曲并打开歌词页，在播放页设置的「注音」中调整。

未切换来源时，仍按原来的网易云音译方式注音；选择词典来源则使用内置 kuromoji + IPADIC 推读音。

自行打包只需安装 Node.js，检出 `standalone` 分支后，在仓库目录运行：

```sh
node tools/pack.js
```

产物为 `builds/jp-furigana-plus.plugin`，按上述步骤安装即可。

## 外部网站注音

| 网站 | 读音来源 | 使用方式 |
| --- | --- | --- |
| [UtaTen](https://utaten.com/) | 网页上的词级振假名 | 自动模式优先使用，也可单独选择 |
| [歌ネット / Uta-Net](https://www.uta-net.com/) | 日文歌词与独立罗马音 | 通过原插件算法对齐到汉字，自动模式下作为备用 |

播放歌曲时先读取本地缓存。没有可用网站缓存时，先显示网易云音译或离线词典注音，同时查询所选网站；仅保存人工纠音的文件不会阻止这次获取。获取成功后，只替换能够与原歌词匹配的读音，**保留原歌词文字、翻译和时间轴**。

搜索先核对歌名与歌手。如果歌手名称写法不同，会尝试歌名搜索，再用多个歌词片段核对候选。无法唯一确定歌曲时继续使用本地注音，不直接套用第一条搜索结果。整套搜索与歌词核对流程算一次尝试。

**「仅查询 UtaTen」限制的是网站来源。** 它不会请求或使用歌ネット的缓存，但加载期间、未匹配的歌词行仍会使用网易云音译或词典回退。因此，显示“已获取 UtaTen”不代表整首歌的每个词都来自 UtaTen。可通过「查看来源网页」检查网站原文。

### 代理与重新获取

在原插件设置页启用代理并填写地址，例如 `http://127.0.0.1:7890` 或 `socks5h://127.0.0.1:1080`。支持 HTTP、HTTPS、SOCKS5、SOCKS5H；需要已有的代理服务，不支持在地址中填写账号密码。

代理 **仅用于访问歌词网站**，不改变网易云播放、歌曲信息或官方音译请求的网络设置。

- **重新获取当前歌曲**：重新搜索和下载；获取期间及失败后继续显示已有缓存，保留已有人工修改。
- **失败后自动重试**：对超时、连接中断、HTTP 200 空页面等临时故障最多补试三次，换歌或关闭功能时取消旧任务。自动模式先尝试另一个网站，再等待重试；不会重复请求已明确拒绝访问或未匹配的来源。
- **关闭自动重新获取**：仍保留首次获取，只关闭后续自动补试。搜索无结果、版本有歧义等情况不会无限重试。

BetterNCM 插件设置页和 RefinedNowPlayingNext 的「注音」页都会显示获取进度、失败的网站及原因（如搜索页面为空、`curl error 28` 超时、DNS / 代理连接失败、HTTP 状态或歌词不匹配），等待自动重试时也保留原因。HTTP 200 空页面代表网站没有返回有效内容，并不表示它没有收录歌曲；可稍后重试，或将范围改为「自动」尝试另一来源。「仅查询 UtaTen」仍严格限制来源，不会自行切换网站。

## RefinedNowPlayingNext 播放页设置

在 RNP 3.0.2 的播放页设置中，「歌词」后新增 **「注音」**，沿用其按钮、开关和滑块风格，包含：

- 振假名开关、读音来源、外部网站范围。
- 自动重新获取、重新获取当前歌曲、查看来源网页。
- 编辑模式、本地歌词管理。
- 注音大小、不透明度，以及逐字歌词等原有四项兼容设置。

状态区域简要显示匹配到的歌名、歌手和人工修改数量。两处设置同步生效；代理地址与缓存目录在原插件设置页中配置。

该入口由本插件添加，**不需要修改 RNP 插件文件**。商店会根据 `requirements` 识别 RNP 依赖。手动安装缺少 RNP 或未来布局不兼容时，原 BetterNCM 设置页仍保留；这不代表该组合已通过发布版兼容验证。

## 在播放页人工纠音

即使网站有注音，也可能与歌手实际唱法不同，例如歌词写作「戀人」，实际唱作「あなた」。可以在播放页直接修正这些位置：

1. 点击 **「进入编辑模式」**。
2. 鼠标悬浮到独立注音单元，点击输入框，输入对应假名。
3. 按 **Enter** 或点击 **「应用」** 保存；也可取消，或恢复该词的原注音。
4. 完成后退出编辑模式，正常播放时只显示修改后的注音。

**编辑模式下，所有原注音保持原来的位置；修改处原注音原地划掉，新注音显示在它的上方。** 未保存的输入会有提示；保存失败保留输入，换歌后不会把上一首的修改误写入新歌。

**没有网站歌词也能编辑。** 插件会以网易云音译或词典分词为基础，为该歌曲创建本地 JSON，只保存人工修改。没有读音的可编辑汉字单元以「＋」提示。

人工修改优先加载，可单处恢复，也可在管理页恢复整首歌。若重新获取后原文、分词或原读音发生变化，无法匹配的修改仍保留在文件中，但不会强行套用到其他位置。

## 本地歌词缓存与管理

默认存储位置：

```text
<BetterNCM 数据目录>/lyrics/jp-furigana/<网易云歌曲 ID>.json
```

为兼容先前扩展版，此默认目录继续沿用 `jp-furigana`；Plus 的设置、计算缓存及模块标识独立，首次升级会复制旧设置一次并保留原设置。可在设置页自定义完整磁盘路径。缓存不放在插件解压目录内，更新插件时可继续复用；更改目录不会自动搬迁原有文件。

**每首歌始终只有一份歌曲 JSON。** 网站原文与读音保留在原字段中，人工修改额外记录在 `userEdits` 内，不另存一份完整歌词。重新获取网站歌词时也保留人工修改。

打开 **「本地歌词管理」** 可以：

- 查看缓存歌曲数量、空间占用和每首歌的修改数量。
- 按歌名、歌手或歌曲 ID 搜索，或只显示已修改的歌曲。
- 查看原歌词及修改前后的读音，恢复整曲原始读音。
- 点击「播放并编辑」，切换到对应歌曲后进入编辑模式。
- 删除单曲缓存及其人工修改；删除前会确认。

![本地歌词管理](https://github.com/user-attachments/assets/b380a6c5-60d6-4fdf-b93b-64f96619361e)

缓存命中后不重复请求歌词网站。仅有人工修改的本地文件也会长期复用，想再次搜索网站时可点击「重新获取当前歌曲」。保存采用临时文件校验与原子替换，降低写入失败导致原文件损坏的风险。

功能不依赖数据库服务，不增加常驻后台服务。网络与保存组件按需运行并退出；原插件自带的离线词典仍会占用内存，实际开销取决于客户端和歌词页面。

## 注音修复与已知限制

本分支在查词和对齐时兼容部分新旧字形，例如 `會/会`、`戀/恋`、`凜/凛`、`墮/堕`，显示时保留原字。修复 `出會った` 等漏注音情况，为 `堕とす / 堕ちる` 补充语境读音，并在罗马音对齐无歧义时补全部分未知汉字。相邻长注音会预留间距，兼顾原生 ruby 和旧内核的降级排版。

使用时还需注意：

- 网站收录和词典都不保证符合每一次演唱；网站没有歌曲、歌词差异过大或同名版本无法区分时，仍会回退。
- **相同整句在重复演唱中共用人工修改**，目前不按时间戳区分同一句的不同唱法。
- 人工编辑以现有分词单元为单位，不提供任意重分词或歌词原文编辑。
- 删除缓存会同时删除该曲人工修改；建议在批量清理或迁移目录前备份 JSON。
- 原生桌面歌词不支持；其他歌词插件或未来 RNP 版本的布局变化可能需要继续适配。

完整获取策略、缓存结构与使用说明见 [外部歌词与人工纠音说明](docs/external-lyrics.md)，测试覆盖和未验证范围见 [验证记录](docs/validation.md)。

```sh
npm ci

npm test
node tools/test-rnp-dom.js slide noruby

```
