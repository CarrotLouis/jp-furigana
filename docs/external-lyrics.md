# 外部网站读音来源

## 使用

1. 安装 [BetterNCM 1.3.4](https://github.com/std-microblock/chromatic/releases/tag/1.3.4)，将 `jp-furigana.plugin` 放到实际 BetterNCM 数据目录下的 `plugins/`。更新时先退出网易云，备份并移出旧包；若从 Plus 迁移，也先移出 Plus 包。
2. 重启网易云，进入插件设置，将「读音来源」选为「外部网站」。原有默认设置仍为网易云音译。
3. 播放日语歌并打开歌词页。显示顺序为：网易云音译 / 离线词典 → 外部网站成功匹配的读音。原文字形、翻译和时间轴不替换。
4. RNP 设置简要显示匹配到的歌名、歌手、来源与人工修改数量；原插件设置页保留详细诊断。「查看来源网页」在系统浏览器打开来源；「重新获取当前歌曲」忽略缓存并重新搜索。

支持网易云原生网页歌词及上游已经适配的 RNP、LyricBar 等网页歌词容器。1.6.0 增加 [透明桌面注音](desktop-lyrics.md)，复用同一份网站读音和人工纠音。歌曲无可用网易云 ID、歌名或歌手信息时不做自动网站匹配；有歌曲 ID 时可手动指定 UtaTen 页面。

## 两个来源

### 日语触发条件（1.6.2）

外部查询前先检查当前歌曲 ID 的原歌词。完整 LRC / YRC 是主要依据，尚未获取时可复用客户端同曲原歌词；不从翻译、罗马音、歌名、歌手或旧曲 DOM 推断日语。日文制作信息始终从语种判断中排除，不受用户是否关闭「跳过制作信息」影响。纯英文、中文、韩文、纯音乐等无日语原文的歌曲不调用网站，也不读取/刷新网站来源或手动指定页；已有文件保留。

英日混合歌曲保留支持，即使当前显示的段落是英语，也使用整曲原文判定。等待或失败时暂停外部获取，并在两处设置页显示原因；未知语种状态下的重新获取只重查网易云原歌词。人工指定、编辑入口和桌面替代共用这一判断；非日语曲使用原生桌面歌词，不改原桌面开关或注音偏好。没有网站收录的日语歌仍可编辑。

该判断复用现有网易云歌词请求，不逐曲新增百科查询或语言缓存文件。歌曲详情接口不保证提供单曲语种字段，百科标注只在研究时核对，不能把日本歌手或专辑标签当成实际歌词语种。

| 来源 | 获取内容 | 自动查询方式 | 优先级 |
| --- | --- | --- | --- |
| [UtaTen](https://utaten.com/) | 页面 `.hiragana` 内每个词的原文、假名 | 歌名与歌手查询，再校验歌曲页 | 默认第一 |
| [歌ネット](https://www.uta-net.com/) | global 页面成对的日文 / 罗马音行 | 搜歌名，校验歌手，再取对应 global 页面 | 默认备用 |

UtaTen 无需打开打印窗口即可提取公开 HTML 内的振假名。歌ネット的罗马音需要通过原插件算法重新对齐到汉字，有些条目存在机械转换错误。两者都不是准确性保证；在设置中也可只使用其中一个。

「仅查询 UtaTen」表示不访问歌ネット，也不使用歌ネット的缓存；它不禁用加载期间或未匹配行的网易云音译 / 词典回退。原插件设置页仍按当前歌词容器分别显示网站命中、网易云音译回退和词典回退的行数，不能仅凭“已获取 UtaTen”判断每一行都来自网站。

1.6.0 会清理曲名末尾的 feat./cover/翻唱/remix 等附注，优先按原歌手列表顺序逐一查询。以《花 feat. 花譜》、Guiano / 花譜为例，UtaTen 依次尝试「花 + Guiano」「花 + 花譜」；所有歌手均未匹配后才仅按歌名搜索。歌ネット只请求一次歌名列表，并按歌手顺序核对。对最多 5 个同名候选逐一读取歌词，至少有两个不同片段、合计 24 字吻合，并达到取样比例门槛才接受。制作信息和过短片段不作证据；多个候选都吻合时仍拒绝自动选择。曲名中的独立 Cover / Remix 等真实标题保留，清理只针对附注格式。歌手逐一查询、仅歌名查询、候选核对整体算一次尝试，不增加后台循环。

自动模式在第一来源失败或没有唯一匹配结果时尝试第二来源。匹配依赖歌名、歌手和原文，不使用“搜索结果第一条就套用”的方式。多个同名版本不明确时回退。错误会显示在设置中；可手动重试或下一次播放再尝试。

## 手动指定 UtaTen 歌词页（1.6.0）

BetterNCM 设置和 RNP →「注音」均提供「手动指定歌词页」。输入 `https://utaten.com/lyric/…/` 并确认，即直接获取该页面，不再依赖自动搜索的歌名、歌手校验；网页与当前歌词的逐行对齐规则仍保留。仅接受 UtaTen 的 HTTPS 歌词页，不接受搜索页或其他站点。使用「仅查询歌ネット」时，此按钮停用。

每首歌仍只保存一份 JSON，在原结构上增加 `manualSource: { provider: "utaten", url: "…" }`；不额外复制歌词。指定时先保存选择，失败后仍可重试；重新获取继续使用此页，成功后更新原网站数据并保留 `userEdits`。留空确认后删除 `manualSource`，重新执行自动搜索。切换到仅歌ネット时保留但不使用 UtaTen 的指定链接。

## 超时与自动重新获取（1.3.0）

单个网页请求允许连接等待最多 10 秒，包含重定向的整个请求共享约 30 秒网络预算。此前为连接 5 秒、总计 10 秒；慢速直连或代理可能在页面返回前就收到 `curl error 28`。延长等待不保证网站一定可达，期间仍显示网易云音译 / 词典注音。

「自动重新获取」默认选为「失败后自动重试」：超时、连接中断和临时 HTTP 错误会按 3 / 8 / 15 秒间隔补试，每次加载共用最多 3 次重试额度。1.4.0 按完整匹配流程重试：本轮搜索或候选页发生临时网络错误时，下一次重新搜索、核对候选；严格匹配与放宽匹配之间不计作额外重试。成功读取缓存不联网。

选择「关闭」仍会执行首次获取，并取消尚在等待的自动重试；已经发出的请求可正常完成。换歌、关闭注音或切换来源会取消旧任务，并通知正在运行的网络组件退出。手动「重新获取当前歌曲」会开始新的一轮获取。

没有匹配歌曲、同名版本歧义、网页格式变化、HTTP 403/404、证书验证错误等不会自动补试。HTTP 429/503 等响应提供 `Retry-After` 时，等待不会短于服务器要求；超过 5 分钟则结束本轮，不为旧歌曲长时间保留任务。耗尽重试额度后保留原有注音并显示失败原因。

## RefinedNowPlayingNext 设置入口（1.3.0）

检测到 RefinedNowPlayingNext 3.0.2 的播放页设置菜单后，会在「歌词」后加入「注音」，沿用其按钮、开关与滑块样式。包含振假名开关、读音来源、外部网站范围、自动重新获取、重新获取当前歌曲、查看来源网页、大小、不透明度，以及原有四项兼容开关。1.4.0 还增加编辑模式与本地歌词管理按钮，隐藏缓存目录、重试说明长段和歌词容器统计，状态只显示匹配歌曲及歌手。两处设置同步生效，代理和缓存目录仍在 BetterNCM 原设置页管理。

该入口由本插件添加，不修改 RefinedNowPlayingNext 的文件。商店版声明依赖 `RefinedNowPlayingNext`，已适配 3.0.2，客户端范围与其要求保持一致（网易云高于 3.1.11）。菜单重建时会重新接入；手动安装缺失依赖或未来版本布局不兼容时，原 BetterNCM 设置页作为后备入口。只监听菜单变化，不增加定时扫描。

## 代理

勾选「使用代理获取外部歌词」后填写地址，例如：

```text
http://127.0.0.1:7890
socks5h://127.0.0.1:1080
```

支持 HTTP、HTTPS、SOCKS5、SOCKS5H。SOCKS5H 将域名解析交给代理。代理需已在本机或指定服务器运行；插件本身不提供代理服务。不支持在地址中嵌入用户名和密码。

该设置仅用于两个歌词网站。网易云的歌曲信息及音译请求仍使用客户端原有网络方式。关闭此选项时，外部歌词请求直接连接，不继承环境变量中的代理。

请求由 Windows 自带 `curl.exe` 完成，因此不受浏览器 CORS 限制，也无需全局更改网易云的代理。PowerShell 只用于启动、收取结果和退出，不更改执行策略。所有动态输入作为 Base64 JSON 数据传递，不作为命令执行。TLS 验证保持开启，重定向只允许两个歌词网站的 HTTPS 地址。

1.5.3 为 UtaTen 请求补充固定的 `Referer: https://utaten.com/`，与网站正常搜索时的来源一致。实测缺少该头的搜索请求会收到 HTTP 200、`Content-Length: 0`，相同网络及查询参数补上该头后返回正常候选列表；仅改 User-Agent 无法解决。该请求头不包含本地路径、代理配置或正在播放的歌曲信息。

## 缓存与资源占用

默认路径：`<BetterNCM 数据目录>/lyrics/jp-furigana/<网易云歌曲 ID>.json`。例如默认 BetterNCM 安装为 `C:\betterncm` 时，路径是 `C:\betterncm\lyrics\jp-furigana\`。

可在设置中指定完整磁盘路径，例如 `D:\MusicData\Lyrics`。修改路径后旧文件保留，新目录没有缓存的歌曲会重新查询。缓存放在插件解压目录之外，避免更新插件时被删除。

每首 JSON 保存网站原文、读音、来源地址、歌曲信息和获取时间；不保存音频、网页广告、脚本或网易云账号数据。缓存长期复用，不自动刷新。格式损坏时丢弃读取结果并重新获取；写入失败时本次仍可显示，状态栏会提示。可从本地歌词管理页搜索、查看与删除；删除前会确认，同曲人工修改也会一起删除。

缓存命中时没有网站请求，也不启动网络进程。网络未命中时串行执行有限次请求；网站获取不新增常驻服务、监听端口或全曲库爬取任务。每次请求结束后 PowerShell/curl 退出。日常内存只保留当前歌曲及其对齐索引；管理页打开时读取缓存元数据，列表每批显示 50 首，关闭后不再保留页面；原插件自带的 kuromoji 词典仍然使用。可选桌面绘制组件的按需回环连接另见 [桌面注音](desktop-lyrics.md)。

`requests/` 是网络结果的短期交换目录，单次请求消费后删除自己的文件。程序被强制结束时可能残留文件，可在网易云退出后清理该目录。

## 人工纠音与本地歌词管理（1.4.0）

在 RNP「注音」或原插件设置中点「进入编辑模式」。鼠标悬浮到独立注音单元会出现输入框，点击后输入假名，Enter 或「应用」保存；日文输入法选字的 Enter 不会误保存。支持平假名、片假名和长音符，最终按全局假名类型显示。合并后的长注音单元也可编辑，单次自定义读音上限为 1000 个假名。没有读音的汉字单元以「＋」提示。

编辑模式下所有原注音仍贴近汉字，保持同一基线；修改处的原注音原地划线，新注音显示在它的上方。退出编辑模式后，只在正常注音位置显示有效的新读音。「恢复原注音」撤销单处修改；管理页可恢复全曲。未保存时退出、取消或从管理页换歌会提示；保存失败保留输入。外部操作切换歌曲时，旧输入不会写入新歌曲，编辑框提示复制或取消。

每首歌仍只保存 `<歌曲 ID>.json`。网站缓存保留 schema 1 和原有 `lines` 等字段，额外加入 `userEdits` 数组。条目记录来源、原句、词的字符偏移、词面、原读音、自定义读音与修改时间；不会另存整份歌词副本。修改优先于匹配到的网站注音；重新获取网站数据也保留全部修改。原位置、词边界或原读音发生变化的条目仍保留，但不强行套用，可以在管理详情中检查。

没有网站匹配时也能进入编辑模式：新建 `provider: "local"`、`url: ""`、`lines: []` 的同曲 JSON，以网易云音译／词典分词为基准，只保存修改条目。以后获取成功，仍在原文件内加入网站数据并保留修改。仅有人工纠音的文件不算网站缓存，下次播放仍会尝试获取，也可手动点击「重新获取当前歌曲」。在网易云音译／词典模式进入编辑时，同样先尝试获取网站数据，再使用本地纠音回退。

请求中第一次点击编辑，仅显示红色「将中断网站注音获取，再次点击进入编辑模式」；第二次点击才取消本轮请求并进入编辑。完成请求、换歌、开始新请求会清除确认，不会误取消下一轮任务。迟到结果不能覆盖编辑文件。

管理页显示所有可识别的歌曲 JSON、空间占用、修改数量，可按歌名／歌手／ID 搜索及只看已修改。损坏文件标记为不可操作，空间统计不含无法读取的文件。「播放并编辑」请求网易云播放该 ID，确认当前歌曲已切换后才启用编辑；无法切换会提示手动播放。

写入先校验原文件未被其他保存覆盖，再通过临时文件原子替换；校验或磁盘写入失败不会清空已保存文件。临时保存文件在成功后清理，强制退出时可能留下 `.write-*` 文件，待网易云退出后可检查清理。所有网络与保存组件均按需退出，没有常驻本地服务。

限制：当前定位使用“整句原文＋词内位置”，完全相同整句在多次演唱中共用修改，暂不按时间戳区分重复副歌。网站未匹配的行仍使用网易云／词典分词，并非所有字都会被拆成单字。管理页与内联编辑均为本插件添加，不修改 RNP 包。

## 对齐与漏注音修复

- 比对时忽略空白、标点差异，并兼容少量日文新旧字形；显示时始终保留网易云原文。
- 1.2.1 补齐歌词中的 `彈/弾`、`焰/焔`、`廻/回`、`涂/塗`、`傳/伝`、`說/説`、`咒/呪`、`駈/駆`、`溯/遡`、`淚/涙`、`絕/絶`、`冲/衝` 等字形对应。新增对应只用于歌词，不扩展歌名 / 歌手校验或改写搜索词。
- 逐句对齐不再依赖个别词对名单。复用当前歌曲已加载的完整原歌词，用前后唯一匹配的歌词限定段落；两个锚点之间只有一个客户端歌词行、对应 1–3 个网站行时，可确认这一行的对应关系，包括短句和不同字数的写法。重复原句在某次出现中缺少足够上下文时，不能借用其他出现位置的结论。
- 缺少足够前后文时，仅接受至少 10 个规范化字符、相似度达到 80% 的完整句候选。优先精确匹配，多个相近候选给出不同读音时回退；不会把任意近似句强行当成同一句。歌名、歌手及搜索结果核对规则保持不变。
- 确认对应行后，按字符位置对齐替换、增字、缺字和假名差异，始终保留网易云原文字形，把网站读音完整映射过来。存在多条同样可行的字符对齐路径时，合并边界不明确的相邻单元并保留网站的整段读音，不猜每个字该分到哪个音。匹配成功的这一句不逐词混入网易云读音；没有可确认的对应关系或网站读音无法解析时，才按原有规则整句回退。
- UtaTen 使用网站提供的振假名；歌ネット先基于网站原文解析其罗马音，再映射回网易云原文，避免用不同的底字重新推读音。人工纠音仍优先，网站数据与 `userEdits` 结构保持不变。对齐只使用内存中的同曲原文，不增加网络请求；旧缓存可直接使用新算法。
- 支持网站连续 2–3 行合并为客户端一行；客户端长行片段也可匹配网站整行，但不会从中间切开一个振假名单元。
- 同文出现不同读音、同名多版本、原文变化过大时不强行套用。网站没有时间戳，无法解决所有重复演唱中的读音差异。
- 词典查词前兼容 `會/会`、`戀/恋`、`凜/凛`、`墮/堕` 等字形，查词后恢复原字和偏移，修复例如 `出會った` 的漏注。
- `堕とす / 堕ちる` 补 `お`，不把 `堕落` 的 `だらく` 错改成 `お`。
- 原算法会直接跳过词典不认识的汉字。新算法允许这些汉字参与罗马音对齐；只有全行可行对齐给出同一读音时才填入，不猜未知词内部的分词位置。
- 修复“漏注”不等于修正音译本身。网易云音译中若多了一个音节，插件不能凭空知道实际演唱；优先 UtaTen 可覆盖不少这样的情况。

升级到 1.2.1 后，已有网站 JSON 缓存会直接使用新的匹配逻辑，无需删除缓存或重新下载歌词。其他无法核对的文字差异仍会回退；本次修复不保证整首歌所有位置都能匹配。

## 功能范围

本插件包含网站来源、JSON 人工纠音、缓存管理及读音修复。旧独立原型、SQLite 与常驻本地服务未包含在本插件。

配置迁移、外部内容授权状态及商店分发方式见 [构建与商店分发](distribution.md)。
